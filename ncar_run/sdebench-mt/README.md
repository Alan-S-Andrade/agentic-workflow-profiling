# sdebench-mt: multi-tenant SWE-bench on one Vista GH200 node

N concurrent agent tenants (mini-swe-agent) share one Qwen3.8-27B vLLM server on the
GH200 GPU. Each SWE-bench instance a tenant works on runs in its own Cloud Hypervisor
microVM (KVM, unprivileged, vsock-only) built from the official swebench arm64 eval image.

```
host (Grace, 72 cores, NUMA0 120 GB)                        GPU (H100, 96 GB HBM)
 tenant 0..N-1 (processes)  --HTTP-->  vLLM (apptainer, cores 0-7) --> Qwen3.8-27B BF16
   └─ mini-swe-agent DefaultAgent
       └─ MicroVMEnvironment --vsock(52)--> microVM: ro rootfs (instance image) + private overlay disk
                                             └─ replay-agent (JSON-line exec server), /testbed
```

## Layout
| path | what |
|---|---|
| `env/` | uv + Python 3.12 venv (`env/venv`): mini-swe-agent 2.4.6, swebench 5.0.2 |
| `models/Qwen3.8-27B` | BF16 weights (52 GB) |
| `containers/vllm-openai-v0.30.0.sif` | vLLM arm64 image |
| `vm/bin`, `vm/kernel/Image` | cloud-hypervisor v53.0 static aarch64, ch-release 6.16.9 arm64 kernel |
| `vm/guest/` | `replay-agent` (vsock exec server) and `init` (overlay root, PID 1) |
| `vm/images/<instance>.ext4` | per-instance guest rootfs (`vm/build_instance.sh`) |
| `configs/instances.txt` | selected SWE-bench Verified instances (arm64 image available) |
| `configs/instances_ok.txt` | subset whose gold patch resolves offline in a VM (used by runs) |
| `configs/mini.yaml` | generated by `configs/make_mini_config.py` (swebench.yaml + local vLLM) |
| `sdebench_mt/` | `vmm.py`, `microvm_env.py`, `tenant.py`, `driver.py`, `metrics.py`, `swebench_eval.py`, `gold_check.py`, `analyze.py` |
| `slurm/` | `probe.slurm`, `build_images.slurm`, `serve_smoke.slurm`, `sweep.slurm`, `serve_vllm.sh`, `common.sh` |
| `runs/` | job outputs: `runs/<jobname>_<jobid>/N<n>/` |

## Run
```bash
cd $WORK/sdebench-mt/runs
sbatch ../slurm/build_images.slurm        # images + vLLM sif + gold check (idempotent)
sbatch ../slurm/serve_smoke.slurm         # vLLM + N=1 and N=4
sbatch ../slurm/sweep.slurm               # N in 1 2 4 8 16 32 (NS="..." JOBS_PER_N=.. to override)
env/venv/bin/python sdebench_mt/analyze.py runs/sdebench-sweep_<jobid>
```
Knobs (env): `MTP=1` (MTP speculative decoding), `MAX_MODEL_LEN`, `GPU_UTIL`, `MAX_NUM_SEQS`,
`VLLM_CPUS` (default 0-7), `VM_CPUSET` (default 8-71); driver flags `--vm-vcpus`, `--vm-mem-mb`,
`--stagger-s`, `--min-mem-frac` (admission stops below 10% host MemAvailable).

## Outputs per N
- `results.jsonl`: one row per instance run (tenant, boot/agent/eval seconds, calls, resolved).
- `tenants/tNNN/<iid>.events.jsonl`: per LLM call (duration, prompt/completion/cached/reasoning tokens) and per tool exec (duration, rc).
- `tenants/tNNN/<iid>.traj.json` / `.patch`: agent trajectory, submitted patch.
- `samples.jsonl`: 1 Hz vLLM metrics (running/waiting, KV %, prefix hits, TTFT/queue sums), host MemAvailable, per-VMM RSS/CPU.
- `gpu.csv`: 1 Hz nvidia-smi.

## Caveats
- VMs have no network (unprivileged: no tap). Instances whose tests need network (e.g. psf/requests) are excluded by the gold check.
- Guest files are owned by the build uid (unprivileged extraction); root in the guest is unaffected, and git's `safe.directory=*` is set.
- Evaluation runs in the same VM after resetting /testbed to base_commit and re-applying the patch (mirrors swebench `run_evaluation`), not in a fresh container.
